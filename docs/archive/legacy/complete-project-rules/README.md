# 📘 Project Rules Overview

This project uses a modular rule system to ensure consistency, scalability, and maintainability across development, testing, deployment, and UI/UX.

## 🗂 Included Rule Files

### 🔐 `integration-rules.md`
Defines protocols for integrating new modules, APIs, and databases. Covers project understanding, architecture awareness, and modularity expectations.

### ✏️ `edit-change.rules.md`
Guidelines for making structural or logic edits. Prevents accidental regressions and enforces planned change behavior.

### 🛠 `troubleshooting.rules.md`
Troubleshooting checklist to handle bugs and errors methodically. Ensures one-step-at-a-time debugging with rollback capability.

### 🚀 `advancement.rules.md`
Rules for scaling the project or introducing major features. Focuses on forward compatibility and design flexibility.

### 🎨 `ui.rules.md`
UI/UX rules for maintaining visual consistency, mobile responsiveness, and accessibility compliance.

### 🔐 `security.rules.md`
Security best practices for input sanitization, authentication, environment protection, and access control.

### ✅ `testing.rules.md`
Mandates the creation and execution of tests for all features. Enforces regression-proofing via automated and manual tests.

### 🚀 `release.rules.md`
Policies for versioning, staging, production release, and rollback planning. Ensures smooth and safe deployment.

## 📌 How to Use

- Follow the relevant `.rules.md` file before starting any new task.
- Reference them in all AI prompts or team briefings.
- Keep this folder in root `/rules/` for visibility.
- Update rules as the team/process evolves.
